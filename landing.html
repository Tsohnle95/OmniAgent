Why OpenShell

The agent, with nothing hidden.

Every capability below is shipping in the app today — not a roadmap.

Live red/green diffs

The main process watches the repo with fs.watch, so every change — yours or the agent's — hits the editor the moment bytes land, diffed against its first-known baseline.

A timeline that thinks

Streaming markdown, collapsible reasoning, grouped exploring context, tool cards, clickable subagent tasks, and permission prompts docked right where you need them.

Concurrent sessions

Open another workspace and it becomes a second agent panel with the same resize and tray behavior. Editor, tree, usage, and terminal follow whichever panel is focused.

A real editor, not a preview

Monaco under your fingers: fully editable, autosave and ⌘S, an Edit/Diff toggle on every tab, and W3C HTML/CSS validation surfaced as in-editor markers.

Terminals that belong

A node-pty terminal tray per workspace. Run the commands the agent suggests, right under the diff, and watch the file tree react in real time.

Durable by default

Interrupted saves and renames never lose a byte — original and proposed artifacts persist with Open/Acknowledge actions. Acknowledgment never deletes anything.

How it works

Three moves to momentum.

The Electron main process is the only thing that talks to opencode2 — sessions, SSE streaming, and file watching all stay on your machine.

1

Open a repo

OpenShell discovers or spawns your opencode2 service and creates a session bound to that directory.

2

Prompt the agent

Events stream over SSE, coalesced per directory and batched into a calm, readable timeline — never a wall of noise.

3

Watch every change

The editor mirrors the workspace live while baselines turn each touch into a legible diff you can edit or accept.
