# OpenShell Rebrand — 100 Name Directions

## The idea, fleshed out

Today OpenShell is welded to one power source: opencode2. The rebrand claims the
broader category — **a harness-agnostic AI IDE**: a native desktop cockpit where
*any* coding agent or harness (opencode, Claude-style CLIs, custom runners, MCP
backends, future runtimes) plugs in as a swappable power source behind one
consistent GUI.

The product thesis in one line:

> **The GUI is the constant. The agent is the plugin.**

What stays ours regardless of which agent is connected: streaming transcripts,
live per-file diffs, permission gates, terminals, multi-panel concurrent
sessions, workspace watching. What becomes interchangeable: the brain. That is
an adapter story, a socket story — so the name should evoke the *host, harness,
dock, or cockpit*, never a specific agent, and ideally not even "shell"
(terminal baggage + the opencode collision that motivated this).

## What a good name must survive

- ≤ 3 spoken syllables, legible to developers at a glance
- Works as a CLI command (`$ npx <name>`), a menu-bar title, and an app icon
- Describes the socket/host — room to plug in agents that don't exist yet
- Plausible `.dev` / org handle; no direct collision with a famous dev tool
  (everything below still needs trademark + domain checks before committing)

Legend: ⭐ = personal shortlist picks.

| 3 | **Roundhouse** | Every engine welcome, none special; warm industrial soul matches the UI |

## Next steps before falling in love

1. Trademark screening (USPTO/EUIPO) on the shortlist — especially Harness, Helm, Ember-class generics.
2. Domain + handle sweep: `.dev`, `.app`, GitHub org, npm/crates/Homebrew names.
3. Say each finalist out loud in sentences: *"I left it running in ___ overnight."*
4. Pair each with the logo gallery (`logo.html`) — Patchbay wants a jack field, Nacre wants iridescence, Roundhouse wants the fan-shell turned into a turntable.
